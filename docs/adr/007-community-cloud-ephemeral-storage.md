# ADR-007: Эфемерный диск в Community Cloud и непрерывная синхронизация с GitHub

- **Статус:** Принято
- **Дата:** 2026-11-15
- **Контекст:**
  Для максимальной экономии бюджета система ATLAS разворачивается на серверах RunPod Community Cloud (например, 2× RTX 3090 или 1× A40) без подключения платных постоянных сетевых томов (Persistent Volume / Network Volume). В качестве хранилища используется Container Disk объёмом 75–80 ГБ, который полностью удаляется при завершении сессии (Terminate пода). При этом архитектура обязана сохранить полную обратную совместимость для будущего переезда на Secure Cloud с постоянным диском при смене оборудования.

## Решение

1. **Эфемерный Container Disk 75–80 ГБ**:
   - При создании пода в RunPod Community Cloud постоянный том (Volume Disk) не подключается (0 ГБ или отключён), что исключает постоянные ежемесячные списания за хранение.
   - Задаётся `Container Disk = 75–80 ГБ`. Кэш моделей Hugging Face размещается по стандартному пути `HF_HOME=/workspace/hf_cache`.

2. **GitHub как единый источник истины**:
   - Поскольку диск пода уничтожается при Terminate, код, история сессий `sessions/` и `PROJECT_MEMORY.md` хранятся в удалённом Git-репозитории.
   - Входная точка `docker/entrypoint.sh` при старте автоматически клонирует или обновляет репозиторий через переменную `PROJECT_REPO_URL` и авторизованный токен `GITHUB_TOKEN`.

3. **Непрерывный авто-пуш и команда `/save`**:
   - В `src/mobile_bridge.py` после каждой успешной правки кода и сборки выполняется не только локальный коммит, но и автоматический `git push`.
   - В Telegram-бот добавлена команда `/save` (или `/push`), позволяющая принудительно зафиксировать все изменения перед удалением пода.

4. **Двухуровневый контроль свободного места в entrypoint.sh**:
   - При старте проверяется наличие модели в кэше. Если её нет и свободно менее 40 ГБ — удаляются каталоги неактуальных моделей (страховка при смене поколения GPU на постоянном диске).
   - Если после очистки (или на новом диске) свободно менее 40 ГБ — отправляется Telegram-оповещение и запуск останавливается.

## Последствия

- **Плюсы:**
  - Нулевая абонентская плата за неактивные сетевые диски в RunPod. Оплата списывается строго поминутно только за фактически отработанное время GPU.
  - Мгновенное восстановление рабочего состояния проекта на любом инстансе в один клик.
  - Полная сохранность кода и контекста благодаря непрерывной выгрузке коммитов в GitHub.
- **Минусы / Компромиссы:**
  - При каждом новом создании пода модель скачивается заново (благодаря `hf_transfer` на скорости гигабитного канала RunPod это занимает 3–5 минут).
