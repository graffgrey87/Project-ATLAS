# ADR-001: Один контейнер с supervisor

## Статус
Принято

## Контекст
Нужно определить, как запускать vLLM и mobile_bridge.py на RunPod:
- Один контейнер с менеджером процессов (supervisor).
- Два контейнера с docker-compose и bridge-сетью.

RunPod работает по модели «один Pod = один контейнер». Два процесса (vLLM
и bridge) нуждаются в общем доступе к `/workspace` и `localhost:8000`.

## Решение
Один контейнер `atlas` с supervisor (`nodaemon=true`) как PID 1.
Supervisor управляет процессами vLLM и mobile_bridge.py с `autorestart`.

## Альтернативы
- **Два контейнера:** требует bridge-сеть, named volume, усложняет
  конфигурацию RunPod. Оставлен как fallback при конфликте vLLM/PyTorch.
- **systemd:** избыточен для двух процессов, не предназначен для контейнеров.
- **s6-overlay:** мощнее supervisor, но менее распространён и сложнее в настройке.

## Последствия
- ✅ Простая конфигурация RunPod.
- ✅ Тривиальный доступ к общим ресурсам (файлы, localhost).
- ⚠️ Конфликт зависимостей vLLM/PyTorch — риск, требующий smoke-теста.
- ⚠️ При падении одного процесса supervisor перезапускает только его, не весь Pod.
