## 2. Реальные метрики производительности (сняты с пода)

### 2.1. Скорость и кэширование vLLM
* **Avg Prompt Throughput (prefill):** `326 – 546 tok/s` в обычном режиме, до **`1 361.4 tok/s`** на длинном контексте с Prefix Cache.
* **Avg Generation Throughput (decode):** **`43.7 – 78.1 tok/s`** (среднее ~50 tok/s).
* **Prefix Cache Hit Rate:** **`71.8% – 75.5%`** (высокая эффективность повторного использования системного промпта и истории).
* **Multimodal (Vision) Cache Hit Rate:** **`92.3% – 97.6%`**.
* **GPU KV Cache Usage:** **`3.9% – 5.6%`** при 1 активном пользователе (значительный запас для 32K контекста).

### 2.2. Время выполнения end-to-end запросов в Telegram
* Простые команды (`/start`, `/save`, `/clear`): **`0.16 – 1.5 сек`**.
* Запросы с веб-поиском + чтением документации + сборкой шаблона APK: **`21 – 30 сек`**.
* Сложная автономная разработка + отладка по скриншоту + чтение логов + пересборка + проверка `aapt`/`classes.dex`: **`178 – 306 сек`** (3–5 минут).
* **Сборка Android APK (Gradle 8.11, AGP 8.7.3, Kotlin 2.0.21):**
  * Холодный старт (первая загрузка зависимостей): **`56 сек`**.
  * Повторная инкрементальная сборка: **`~5–20 сек`**.

## 3. Выявленные узкие места и проблемы для анализа

1. **Последовательный Tool Calling без пакетного редактирования**:
   - Каждый `write_file` запускает `git_sync_push` (`add` + `commit` + `pull --rebase` + `push`), что добавляет ~1–2 сек на каждый файл и создаёт много мелких коммитов при генерации 5–10 файлов проекта.
2. **Избыточные вызовы `search_web` / `run_shell_command`**:
   - При поиске свежих версий модель иногда делает 3–5 похожих запросов подряд вместо 1–2 точных, расходуя итерации.
3. **Холодный старт контейнера на эфемерном поде**:
   - Скачивание ~35 ГБ весов модели (~6 мин) + холодная компиляция `torch.compile` (~4–6 мин).
4. **Ограниченность тестирования UI без эмулятора**:
   - В облачном Docker-контейнере RunPod отсутствует `/dev/kvm`, поэтому невозможно поднять аппаратный Android Emulator; внедрены Unit-тесты + **Robolectric** + `lintDebug` (`skills/test_android.py`), но для реального визуального рендера на устройстве нужен либо ADB over TCP/Tailscale к физическому смартфону, либо screenshot-тестирование (Paparazzi/Roborazzi).
5. **Размер контекста при длинных цепочках (до 45 шагов)**:
   - В `sessions/chat_history_386074947.json` размер файла вырос до **89 КБ** за несколько итераций разработки одного приложения; при активном чтении логов есть риск приблизиться к 32K токенов.
