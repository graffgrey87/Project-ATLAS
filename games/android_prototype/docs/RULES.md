# Правила разработки — Android Prototype (Godot 4.4.1)

## 1. Движок и рендерер
- **Версия движка**: строго **Godot 4.4.1-stable**.
- **Рендерер**: `gl_compatibility` (Compatibility) для максимальной совместимости с мобильными GPU и Web/HTML5.
- **Экран**: портретная ориентация (`720x1280`), `stretch/mode = "canvas_items"`, `stretch/aspect = "expand"`.

## 2. Язык и код (GDScript 2.0)
- Использовать **только синтаксис GDScript 2.0** (строгая типизация переменных, аргументов и возвращаемых значений `-> void`, аннотации `@export` / `@onready`, подключение сигналов через `signal.connect(callable)`).
- Синтаксис Godot 3 (`yield`, `onready`, `export var`, `connect("...", self, "...")`) **запрещён**.

## 3. Data-Driven подход
- Никаких «магических чисел» в игровой логике и построении интерфейса.
- Все размеры, отступы, цвета, лимиты и тексты выносятся в конфигурационные словари (`UI_CONFIG`, `COLORS`, `TEXTS`) или кастомные `Resource`-файлы (`.tres`).

## 4. Процедурный Greybox UI на старте
- Сцены `.tscn` должны оставаться минимальными (корневой узел с привязанным скриптом).
- Интерфейс и прототипные элементы на этапе Greybox создаются процедурно в коде (`StyleBoxFlat`, `Control`-контейнеры, `Button`, `Label`), без зависимости от внешних ассетов.

## 5. Touch-First дизайн
- Никаких механик, завязанных на `hover` (наведение курсора), правую кнопку мыши или клавиатурные сокращения.
- Минимальный размер любой интерактивной сенсорной зоны — **не менее `48x48` px** (`debug`-кнопка и элементы управления).
- Ключевые элементы взаимодействия (основные кнопки действия) — **не менее `64x64` px**.
- Для кнопок отключать фокусную рамку (`focus_mode = Control.FOCUS_NONE`), чтобы не возникало артефактов при тапе.

## 6. Safe Area (вырезы и системные панели)
- Весь UI обязан учитывать `DisplayServer.get_display_safe_area()` с корректным пересчётом координат экрана в координаты viewport при `canvas_items` + `expand`.
- Интерактивные элементы не должны попадать под чёлки, вырезы камеры и системные жесты навигации.

## 7. Обязательный Debug-оверлей
- В каждом прототипе и игре обязательна кнопка `Debug` в верхнем углу (в пределах Safe Area), открывающая/скрывающая диагностический оверлей.
- Оверлей должен отображать минимум:
  - текущий FPS;
  - разрешение окна и viewport;
  - прямоугольник `SafeArea` и вычисленные отступы;
  - последние записи внутреннего лога событий.
